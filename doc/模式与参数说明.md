# 模式与参数说明

## setting参数说明

- **setting**：任务全局设置，控制并发、报告、前后置校验等。
  - **speed.channel**：并发通道数，控制同步并发度，默认为1。
  - **reportPath**：同步报告输出路径，支持绝对路径和相对路径。
  - **enablePreCheck**：是否启用前置校验（如表结构、权限等），布尔值。
  - **enablePostCheck**：是否启用后置校验（如数据量、校验SQL等），布尔值。

### 通道类型（channelClass/channelPath/channelMemoryCapacity）参数说明

- **channelClass**：通道类型，支持 memory（默认）、buffered。决定数据同步时的通道实现。
- **channelPath**：文件通道/缓冲通道的磁盘文件路径，默认 ./channel.tmp。
- **channelMemoryCapacity**：内存通道/缓冲通道的内存队列容量，默认 10000。

#### 典型配置示例
- **memory内存通道**
    ```json
    "setting": {
      "speed": { "channel": 2 },
      "reportPath": "C:/pro/paipi_db/local_test/temp/report_file.json",
      "enablePreCheck": true,
      "enablePostCheck": true,
      "channel": {
        "class": "memory",
        "memoryCapacity": 10000
      }
    }
    ```
- **buffered缓冲通道（兼顾速度和容量）**
    ```json
    "setting": {
      "speed": { "channel": 2 },
      "reportPath": "C:/pro/paipi_db/local_test/temp/report_file.json",
      "enablePreCheck": true,
      "enablePostCheck": true,
      "channel": {
        "class": "buffered",
        "memoryCapacity": 10000,
        "path": "./channel_file"
      }
    }
    ```

#### 适用场景说明
- **memory**：速度最快，适合数据量不大、实时性要求高的场景。
- **buffered**：内存+磁盘混合，适合数据量波动大、既要高吞吐又要高可靠的场景。

## transformer参数说明

transformer 用于在数据同步过程中对每条记录进行灵活的数据清洗、转换、脱敏、加密等处理。支持链式调用、参数化配置、内置与自定义扩展。

### 配置格式
```json
"transformer": [
  { "name": "trim", "parameter": { "columnIndex": [1, 7] } },
  { "name": "replace", "parameter": { "columnIndex": [7], "oldValue": "简介", "newValue": "自我介绍" } },
  { "name": "filter", "parameter": { "columnIndex": [2], "value": "18", "op": ">" } },
  { "name": "dateformat", "parameter": { "columnIndex": [6], "fromFormat": "yyyy-MM-dd HH:mm:ss", "toFormat": "yyyyMMddHH" } },
  { "name": "md5encrypt", "parameter": { "columnIndex": [1] } }
]
```

### 支持的内置transformer及参数
| name         | 作用           | 主要参数（parameter）         | 说明/示例 |
|--------------|----------------|------------------------------|-----------|
| trim         | 去除首尾空格   | columnIndex                  |           |
| replace      | 字符串替换     | columnIndex, oldValue, newValue |         |
| filter       | 过滤记录       | columnIndex, value, op(=,!=,>,<) | 只判断第一个字段 |
| dateformat   | 日期格式转换   | columnIndex, fromFormat, toFormat | 支持String/DateColumn |
| md5encrypt   | MD5加密        | columnIndex                  |           |

### 注意事项
- 支持多transformer串联，顺序影响结果。
- 字段类型需为StringColumn/DateColumn，非目标类型自动跳过。
- 参数缺失、索引越界、类型不符时自动跳过并输出日志，不影响主流程。
- filter只判断columnIndexSet的第一个字段。
- dateformat支持字符串和日期类型，格式不符时有详细日志。

## writeMode参数说明

- **writeMode**：控制数据库写入时的主键/唯一键冲突处理策略，支持以下模式：
  - **insert**：直接插入，主键/唯一键冲突报错（所有数据库均支持）。
  - **replace**：主键/唯一键冲突时先删除再插入（MySQL支持，PostgreSQL不支持，HBase不支持）。
  - **update**：主键/唯一键冲突时更新对应记录（MySQL: ON DUPLICATE KEY UPDATE，PostgreSQL: ON CONFLICT DO UPDATE，HBase不支持）。
  - **ignore**：主键/唯一键冲突时跳过该条记录（MySQL: INSERT IGNORE，PostgreSQL: ON CONFLICT DO NOTHING，HBase不支持）。

- **各数据库支持情况**：
  | 数据库       | insert | replace | update | ignore |
  |------------|--------|---------|--------|--------|
  | MySQL      | 支持   | 支持    | 支持   | 支持   |
  | PostgreSQL | 支持   | 不支持  | 支持   | 支持   |
  | HBase      | 支持   | 不支持  | 不支持 | 不支持 |

- **配置示例**：
  ```json
  {
    "job": {
      "content": [{
        "writer": {
          "name": "Mysql",
          "parameter": {
            "table": "user",
            "column": ["id", "name"],
            "writeMode": "update"
          }
        }
      }]
    }
  }
  ```

- **注意事项**：
  - HBase 只支持 insert，其他模式会报错。
  - PostgreSQL 的 update/ignore 需目标表有主键，否则报错。
  - 具体SQL语法由各Adapter自动适配，无需手动拼接。

## 模式0：DB_TO_FILE：拉数将表的数据落成文件（支持csv、parquet、json等多种格式，分块/单文件均可）
- 用途：将数据库表数据批量导出为文件，支持多种格式（csv、parquet、json等），可分块、可单文件，详见 fileType、isChunk、chunkSize 参数。
- 典型数据源：Mysql、Hive、PostgreSQL
- 参数结构：
  - job.content[].common（必需，数据库连接、表、字段、导出路径等）
- 样本：
```json
{
  "job": {
    "setting": {
      "speed": { "channel": 1 },
      "reportPath": "C:/pro/paipi_db/local_test/temp/report_file.json",
      "enablePreCheck": true,
      "enablePostCheck": true
    },
    "sqlMode": 0,
    "content": [{
      "common": {
        "name": "Mysql",
        "parameter": {
          "connection": { "ip": "192.168.232.100", "port": "3306", "username": "root", "password": "admin", "database": "demo" },
          "table": "user",
          "column": ["id", "name"],
          "saveUrl": "./",
          "fileType": "csv",
          "isChunk": true,
          "chunkSize": 10000,
          "sep": ",",
          "where": "id > 1000"
        }
      }
    }]
  }
}
```

- 主要参数说明：
  | 参数名      | 说明                         |
  |-------------|------------------------------|
  | fileType    | 导出文件类型（csv/parquet/json等）|
  | isChunk     | 是否分块导出（true/false）   |
  | chunkSize   | 每个数据文件最大行数         |
  | sep         | 字段分隔符（csv专用）        |
  | saveUrl     | 导出文件保存目录             |

- 注意事项：
  - fileType 支持 csv、parquet、json 等，未来可扩展。
  - isChunk=true 时，导出为分块目录，每个目录下有多个数据文件和 indexMap.json。
  - isChunk=false 时，导出为单层目录，多个数据文件。
  - chunkSize 控制每个数据文件最大行数。
  - 目录结构、indexMap.json、文件命名等详见实现和样例。
  - 其他参数与原有模式一致，详见各数据源配置模板。

### indexMap.json 结构与路径说明

#### 典型导出目录结构示例

- **分块模式（isChunk=true）**
  假设 saveUrl = `C:/pro/paipi_db/local_test/temp/csvChunk/`，channel=2，chunkSize=10000：

```
C:/pro/paipi_db/local_test/temp/csvChunk/
  ├── 0000000001/
  │     ├── 0.csv
  │     ├── 1.csv
  │     ├── ...（每个文件最多chunkSize条数据）
  │  
  ├── 0000000002/
  │     ├── 0.csv
  │     ├── 1.csv
  │ 
  └── indexMap.json
```

- **单层模式（isChunk=false）**
  假设 saveUrl = `C:/pro/paipi_db/local_test/temp/csv/`：

```
C:/pro/paipi_db/local_test/temp/csv/
  ├── 0.csv
  ├── 1.csv
  ├── ...（每个文件最多chunkSize条数据）

```

- 下游解析数据文件时，务必先读取对应目录下的 indexMap.json，按其顺序还原字段。
- indexMap.json 结构和路径在所有 fileType（csv、parquet、json等）下保持一致，便于统一处理。


## 模式1:通用SQL批量执行模式
- 用途：支持单条、多条、批量SQL（文件/分号分隔）、DML/DDL/查询等多种SQL顺序执行，支持最后一条查询结果导出。
- 参数结构：
  - job.content[].common（必需，含connection、sql或sqlFile、可选saveUrl、fileType、isChunk、chunkSize、sep等）
- 样本：
```json
{
  "job": {
    "setting": {
      "speed": { "channel": 1 },
      "reportPath": "C:/pro/paipi_db/local_test/temp/report_file.json",
      "enablePreCheck": true,
      "enablePostCheck": true
    },
    "sqlMode": 1,
    "content": [{
      "common": {
        "name": "Mysql",
        "parameter": {
          "connection": { "ip": "192.168.232.100", "port": "3306", "username": "root", "password": "admin", "database": "demo" },
          "sql": "update user set name='张三' where id=1;delete from user where id=2;select * from user;",
          "sqlFile": "./batch.sql",
          "saveUrl": "C:/pro/paipi_db/local_test/temp/result.csv",
          "fileType": "csv",
          "isChunk": true,
          "chunkSize": 2000000,
          "sep": ","
        }
      }
    }]
  }
}

```
- 主要参数说明：
  | 参数名      | 说明                         |
  |-------------|------------------------------|
  | fileType    | 导出文件类型（csv/parquet/json等）|
  | isChunk     | 是否分块导出（true/false）   |
  | chunkSize   | 每个数据文件最大行数         |
  | sep         | 字段分隔符（csv专用）        |
  | saveUrl     | 导出文件保存路径             |

- 行为说明：
  - 所有SQL顺序执行，只有最后一条SQL如有saveUrl时才尝试导出结果。
  - 最后一条SQL会先执行校验，只有有结果集（如SELECT/CTE/存储过程等）时才会调用downloadData高效导出，否则仅记录日志不导出。
  - 导出时优先使用fileType、isChunk、chunkSize、sep等参数，支持csv/json/parquet等多种格式，分块/单文件均可。
  - 其它SQL（包括中间的SELECT）只执行不导出结果。
  - 兼容所有批量/单条/文件/分号分隔等场景。

- 注意事项：
  - fileType 支持 csv、parquet、json 等，未来可扩展。
  - isChunk=true 时，导出为分块目录，每个目录下有多个数据文件和 indexMap.json。
  - isChunk=false 时，导出为单层目录，多个数据文件。
  - chunkSize 控制每个数据文件最大行数。
  - 目录结构、indexMap.json、文件命名等详见实现和样例。
  - 其他参数与原有模式一致，详见各数据源配置模板。

## 模式2：DB_TO_DB（数据库到数据库高效同步）
- 用途：高效同步两个数据库间的数据，支持异构。
- 参数结构：
  - job.content[].reader（源端详细配置，必需）
  - job.content[].writer（目标端详细配置，必需）
- 样本：
```json
{
  "job": {
    "setting": {
      "speed": { "channel": 1 },
      "reportPath": "C:/pro/paipi_db/local_test/temp/report_file.json",
      "enablePreCheck": true,
      "enablePostCheck": true
    },
    "sqlMode": 2,
    "content": [{
      "reader": {
        "name": "Mysql",
        "parameter": {
          "connection": { "ip": "192.168.232.100", "port": "3306", "username": "root", "password": "admin", "database": "demo" },
          "table": "user",
          "column": ["id", "name"],
          "jdbcUrlParam": {
            "useUnicode": "true",
            "characterEncoding": "UTF-8"
          },
          "session": [
            "set names utf8mb4"
          ]
        }
      },
      "writer": {
        "name": "Postgresql",
        "parameter": {
          "connection": { "ip": "192.168.232.100", "port": "5432", "username": "postgres", "password": "admin", "database": "demo" },
          "table": "user",
          "column": ["id", "name"],
          "jdbcUrlParam": {
            "stringtype": "unspecified"
          },
          "session": [
            "set time zone 'Asia/Shanghai'"
          ]
        }
      }
    }]
  }
}
```
> 注意：TxtFile作为reader或writer时，**没有common块**，只需配置reader和writer。

## 备注
- 0~1模式仅支持Mysql、Hive、PostgreSQL等传统数据源，参数用的是common块。
- 2模式推荐用于所有数据源间同步，参数用reader和writer。
- 各模式参数详见各数据源配置模板文档。

- 详细的transformer插件链配置与用法说明，见《Transformer配置说明.md》

#### 通道参数写法

建议将所有通道相关参数统一放在 `"setting.channel"` 对象下，结构更清晰，便于扩展和维护。

```json
"setting": {
  "speed": { "channel": 2 },
  "reportPath": "C:/pro/paipi_db/local_test/temp/report_file.json",
  "enablePreCheck": true,
  "enablePostCheck": true,
  "channel": {
    "class": "buffered",           // 支持 memory、buffered
    "memoryCapacity": 5000,         // 仅memory/buffered有效
    "path": "./buffered_channel.tmp" // 仅buffered有效
  }
}
```
- `class`：通道类型（memory/buffered）
- `memoryCapacity`：内存队列容量
- `path`：文件通道/缓冲通道的磁盘文件路径

如需兼容老写法，框架会自动优先读取 `setting.channel` 下的参数。
