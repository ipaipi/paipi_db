## 二、适配器文档编写结构与要点

### 1. 文档结构建议
- **一、用途说明**：简要说明该数据源适配器的适用场景、支持的模式、典型用途。
- **二、完整配置样例**：给出典型 JSON 配置，包含 job.setting、reader、writer（如适用），参数尽量全，注释清晰。
- **三、参数说明**：分表格详细列出各参数路径、是否必填、含义，特殊参数（如 session、jdbcUrlParam、分片参数等）需单独说明。
- **四、注意事项**：列举易错点、特殊约束、与其他数据源的差异、分片/认证/类型适配等注意点。
- **五、典型用法场景**：给出常见的实际应用场景，便于新成员理解。

### 2. 样本与参数规范
- 所有 JSON 样本必须包含 job.setting 字段（speed、reportPath、enablePreCheck、enablePostCheck）。
- JDBC 数据源需补充 session（数组）、jdbcUrlParam（对象）字段。
- HBase、TxtFile 等特殊数据源需注明仅支持模式8/9或9，且无 common 块。
- 参数表格需覆盖所有必填/可选参数，格式统一。

### 3. 参考文档清单
- `doc/模式与参数说明.md`：所有模式的用途、参数结构、样本、注意事项。
- `doc/Hive配置模板.md`、`doc/Mysql配置模板.md`、`doc/Postgrepsql配置模板.md`、`doc/TxtFile配置模板.md`、`doc/HBase配置模板.md`：各数据源详细配置模板。
- `README.md`：项目简介、架构、开发规范、插件开发、FAQ、文档索引。
- 相关适配器源码（如 HBaseAdapter.java），确保参数、功能、分片等与文档一致。
- 典型配置样本（如 local_test 目录下各 datasource-config-*.json）。

### 4. 写作建议与流程
1. **预读上述文档和源码，梳理参数与功能点。**
2. **统一文档结构，先用途、再样例、再参数表、再注意事项、再场景。**
3. **所有样本参数尽量齐全，注释清晰。**
4. **参数表格要详细，特殊参数单独说明。**
5. **如有分片、认证、类型适配等特殊点，需单独小节说明。**
6. **FAQ、索引、注意事项要便于新成员查阅。**
